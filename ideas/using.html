Using it

The CLI and curl are the interface, for people and for agents alike. A hook makes the board arrive in an agent's context without the agent having to know kapwa exists. One URL is enough for anything else to learn the rest.

How an agent meets kapwa

Pushed to it the one that matters

A SessionStart hook runs kapwa prime on startup | resume | compact. The board is in context before the first prompt and again after every compaction.

Found by it

kapwa --help opens with the index card and real examples, because agents run --help before anything else. kapwa skills prints the integration guide.

Learned from a URL

GET /api/protocol is the card as plain text. /.well-known/ names the node, its collective and its peers.

MCP is deliberately absent. Reported cost is tens of thousands of tokens per operation against roughly 200 for a CLI call. If a harness can't shell out, a thin wrapper over the CLI is a day's work; until then it isn't built.

Hook wiring (kapwa setup claude)

{
  "hooks": {
    "SessionStart": [{
      "matcher": "startup|resume|compact",
      "hooks": [{ "type": "command", "command": "kapwa prime --hook" }]
    }],
    "Stop": [{
      "hooks": [{ "type": "command", "command": "kapwa beat --hook" }]
    }]
  }
}

--hook reads the hook JSON on stdin, emits hookSpecificOutput.additionalContext, and records a session.start / session.beat event with the session_id. That's what makes "claimed by a session that hasn't been heard from in 30 min" a fold rule.

Matching on compact is the detail that keeps the board alive in long sessions.

Who this domain says its collective and members are.

/.well-known/kapwa.json

{ "version": 1,
  "collective": "dorkyrobot@felixflor.es",
  "writer": "dorkyrobot/mini",
  "url": "https://kapwa.felixflor.es",
  "nodes": ["mini", "mac2024", "mac2019"],
  "protocol": "/api/protocol" }

One address per collective. A new node needs only this URL; it reaches out, and both directions of sync ride that connection.
