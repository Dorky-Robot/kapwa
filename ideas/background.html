Background

The reasoning the other pages stand on: what kind of thing this is, what MCP and Scuttlebutt teach about staying small, which real-world coordination systems already solved parts of it, and the prior art among agent tools.

The mental model: a ledger of commitments

Not a task tracker and not a chat. The best theory for this is Winograd & Flores's conversation for action: all coordination is a loop of four speech acts, and work goes wrong when a loop is left open at one of its joints.

kapwa is a shared, append-only record of who has promised what to whom. Coordination happens by leaving marks, not by sending messages. Every mark is a speech act by a named party. Humans and agents use the same verbs; they differ in authority, not in kind.

"Leaving marks" is stigmergy — how ants and Wikipedia coordinate. Nobody needs to know anybody: you read the environment, act, and leave a trace. It's the real answer to board-vs-bus, and it's why pull replication fits.

What happened to MCP

Context cost

Reported figures: a typical MCP operation costs 32k–82k tokens because the server's whole schema lands in the context window; the equivalent CLI call is around 200.

Ceremony

Three transports in eighteen months, an OAuth story bolted on late, servers that mirrored whole REST APIs. "He built a CLI replacement in 30 minutes" was the tell.

What won instead

A CLI and a markdown file. Agents already know how to run tool --help and read text. The pragmatic frame now: CLI for the inner loop, MCP only where you need multi-user plumbing.

So MCP moves from "next" to "maybe, as a wrapper, if someone asks." The CLI and curl are the interface.

Seven lessons from MCP and connectors

1 · Standardize description, not behavior

MCP won because tools describe themselves in natural language and the model reads that at runtime. The board's rules belong in the text the agent sees, not in docs it never opens.

2 · The smallest primitive wins

MCP shipped tools, resources and prompts; the world adopted tools. Every new kind is one more thing every harness must learn. Stay under ten verbs.

3 · Context is the scarce resource

The backlash against connectors is tool-flooding; the fix was progressive disclosure (deferred tools, skills loaded on demand). prime gets a token budget; everything else is on request.

4 · Outcome verbs beat CRUD mirrors

Servers that expose a REST API one-to-one work badly. claim and hand off work; PATCH /items/:id doesn't.

5 · Identity can't be bolted on

MCP added OAuth late and it still hurts adoption. We have key = name from day one. Keep it that simple.

6 · Descriptions are an injection surface — so is our board

A note written by agent A is read by agent B. That is a prompt-injection channel between agents, including ones owned by external users. Board content must be framed as data, never instructions, and by is what lets a reader weigh it. The most important thing we haven't designed for.

7 · Transports churn; dumb wires survive

stdio → SSE → streamable HTTP in eighteen months. JSON lines over HTTP will outlive all of them.

ATC: handoff with readback

claude  offer sp-7f3k2 → grok-cto
        situation: EV brand approved, number attached
        done: campaign filed · next: attach to messaging svc
        watch: profile is ISV now, not Direct

Mission command: intent on the item

$ kapwa request "Reclass company profile" --to a2p-ops \
    --why "Kita SMS can't ship until the company can own a Brand" \
    --done-when "Twilio shows profile type = ISV"

Layer-2 vocabulary: the ten verbs

Written before "keep it small." These are optional conventions a node may fold or ignore; day one is four.

Which metaphor is it?

The metaphor decides the UI and the words. Three candidates; they aren't exclusive, but one should lead.

The ledger of commitments lean

Rows are open loops between named parties. The view is "what's owed to me, what I owe." Strongest on accountability and on humans + agents as the same kind of participant.

you owe (1)     sp-7f3k2  to cto      promised 2h ago
owed to you (2) sp-9k1p0  from grok   done — accept?
                sp-8h2z9  from kapwa  needs your decision

The pass

A rail of tickets everyone can see; you call and you hear "heard." The view is one shared strip, ordered by urgency. Strongest on glanceability and ack culture; weakest on who-owes-whom.

── the rail ─────────────────────────
FIRE  sp-8h2z9  Direct vs ISV?        felix
P0    sp-2m8q1  A2P owner             — open
P1    sp-7f3k2  Kita SMS ↔ A2P        claude heard

The watch log

Who has the watch for what, and the log of reliefs. The view is by area of responsibility. Strongest on ownership and handover; weakest on one-off requests.

kita       lead-kita               since Sep 02

Systems

Beads (bd) steal: prime · setup · ready · hash ids · messages

Steve Yegge's issue tracker for coding agents. The moves that matter for us:

$ bd prime                  # workflow context + memories, for injection
$ bd setup claude           # installs hooks + AGENTS.md snippet
$ bd ready --json           # unblocked work, machine-readable
$ bd update bd-a1b2 --claim # atomic assignee + in_progress
$ bd close bd-a1b2 "done"
  • Hash IDs so many writers create without colliding — their words: "prevent merge collisions in multi-agent/multi-branch workflows."
  • A message issue type with --thread and replies-to: mail in the same ledger as work.
  • JSON-first output everywhere.

Different from us: one database (Dolt) so claims are atomic; ours is many logs so they are not. See D5 in decisions.

Gas Town steal: the Witness skip: the hierarchy

Roles on top of Beads: Mayor distributes, Polecats work (persistent identity, ephemeral sessions), Witness patrols for stuck/dead workers, Refinery serializes merges. Humans post to a "wanted board" and stamp completed work.

The reusable idea is the Witness: somebody's job is noticing stale claims. For us that can be a fold rule over session heartbeats rather than an agent. The org chart itself is the pattern paddo.dev argues against ("operational roles over a durable ledger" works; "simulating an org chart" doesn't).

Blackboard MCP steal: register/heartbeat/stale · claim verdicts skip: file & build locks

Cross-session coordination for Claude Code on one machine.

bb_register()      # from a SessionStart hook
bb_heartbeat()     # stale after 30 min without one
bb_claim_file()    # → CONFLICT | CLAIMED | OWN
bb_share_knowledge()  # confidence decays, 30-day half-life
  • The claim verb answers with a verdict, not a boolean. Worth copying in the CLI.
  • Sessions are first-class and expire. Worth copying as events.
  • File/build locks are a worktree problem; knowledge-with-decay is diwa's job, not kapwa's.

A2A agent cards steal: the well-known card

Discovery is a JSON document at /.well-known/agent-card.json (RFC 8615): name, url, auth schemes, capabilities, skills. Boring in the good way. Ours:

GET /.well-known/kapwa.json
{ "name":"kapwa", "writer":"mini", "version":1,
  "url":"https://kapwa.felixflor.es",
  "auth":["bearer"], "routes":["/api/writers","/api/log/{writer}",…],
  "nodes":["mini","mac2024",…] }

A new node needs only this one URL.

CLIs for agents (Arcjet, Garbas, gh) steal: all of it

  • Non-TTY → structured output; --json always; treat the JSON as a frozen contract.
  • Exit codes: 0 ok · 1 error · 2 usage · 3 auth. Never exit 0 on failure.
  • Data on stdout, chatter on stderr.
  • --help with real examples: "Claude Code literally runs yourtool --help before trying to use it."
  • A skills command that prints the integration guide.
  • Token from env (KAPWA_KEY); CLAUDECODE=1 is present in the agent's env.
  • Wrap the CLI in MCP later; don't build a second implementation.

Claude Code hooks steal: SessionStart on compact

SessionStart fires on startup | resume | clear | compact | fork and honors additionalContext. compact is the one people miss: re-inject the board after compaction and it survives long sessions. UserPromptSubmit can prepend per turn; Stop receives last_assistant_message.

{
  "hooks": {
    "SessionStart": [{
      "matcher": "startup|resume|compact",
      "hooks": [{
        "type": "command",
        "command": "kapwa prime --hook"
      }]
    }]
  }
}

What kapwa keeps that they don't have

No database

Beads needs Dolt; Blackboard needs one machine. Ours is files and HTTP, which is why an ESP32 can be a peer.

No central writer

Every node writes while offline and syncs later. The price is eventual claims; the payoff is that the laptop in a coffee shop still works.

Identity from the network

People come through Pocket ID; agents through keys; nodes through a shared token. None of the others separate the three.
