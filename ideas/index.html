The coordination layer for the mesh

One process per machine. Agents talk to the node on their own machine; nodes pull each other's logs; people read one board. kita is what a collective knows; kapwa is what collectives owe each other. This site is the design sandbox: the current position, the reasoning behind it, and every open question in one place.

Where we stand, in ten lines

  1. Every writer owns one append-only log; nodes pull each other by seq; the board is a deterministic fold. protocol
  2. The whole protocol fits on an index card, and day one is four verbs: say · take · drop · done, plus ask. Everything else is an optional convention. the card
  3. It is a protocol, not an app: test vectors are the contract; Rust is the reference, with shell, TypeScript and C implementations expected. why
  4. kita and kapwa are complements and never overlap. One question sorts any feature: is it about what we know, or what we owe? the treaty
  5. A collective is one participant: a practice or a brokerage speaks with one voice. writer = the collective, by = the member. as one
  6. kapwa carries other protocols without knowing them, kita included: a reference, a typed payload, and always a plain sentence. riders · carrying context
  7. Identity is nostr's: signed NIP-01 events, NIP-05 names on each collective's domain, membership as a list. People's keys bind through Pocket ID; agents and machines use key files. identity
  8. The CLI and curl are the interface; a hook puts the board in an agent's context at start and after compaction. MCP only if a harness can't shell out. using it
  9. No domain nouns, borrowed from kita: no person's name in a status, no product list. A brokerage must be able to run the same binary as a vet practice.
  10. Keep it small. If it doesn't fit on the card it's a convention, and nobody has to learn it.
